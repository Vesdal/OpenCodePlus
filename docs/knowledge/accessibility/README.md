# Accessibility Foundation

Accessibility is an architectural requirement, not a finishing pass. Make every important action perceivable, operable, understandable, and robust across input methods and assistive technologies.

## Practical baseline

- Use semantic structure, accessible names, roles, values, and state; test screen readers and platform accessibility APIs.
- Ensure keyboard traversal, visible focus, logical order, shortcuts, pointer alternatives, and touch targets.
- Do not rely on color, shape, motion, or sound alone. Pair status with text, iconography, or semantics.
- Support text scaling, reflow, localization, high contrast, reduced transparency, and reduced motion without clipping or loss of function.
- Give forms labels, instructions, constraints, inline errors, summary errors, and recovery paths. Preserve entered data.
- Make loading, success, empty, disabled, error, and destructive states understandable and announced appropriately.
- Verify contrast for text, controls, focus indicators, charts, and meaningful non-text content; use WCAG 2.2 AA as a useful baseline where applicable, while checking native platform requirements.
