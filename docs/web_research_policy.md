# Web Research and Source Acquisition

## Always-on policy
OpenCode may and should use web search/web fetch during development.

Web research is appropriate for:
- current platform APIs;
- current Apple/Windows/Android design guidance;
- package versions;
- official examples;
- bug investigations;
- open-source implementation discovery;
- missing Rust/Slint/Qt knowledge.

## Efficient web workflow
1. Search multiple focused queries.
2. Prefer official sources.
3. Read only the relevant sections.
4. Cross-check important facts.
5. Record durable findings in the curated KB.
6. Record the source and version/date.
7. Do not paste whole pages into the KB.

## GitHub workflow
When a useful repository is discovered:
1. inspect README;
2. inspect LICENSE;
3. inspect package metadata;
4. inspect relevant folders;
5. inspect examples/tests;
6. reuse only the smallest useful part;
7. retain required notices;
8. record provenance.

## Source archive
Large offline sources belong under:

C:\Projects\app-template\docs\sources

The source archive is not part of normal model context.
Use targeted search/read against it.

## Trust
Current web content can be wrong.
For important technical decisions, prefer primary sources and corroboration.
